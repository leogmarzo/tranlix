# App icon and menu bar recording indicator

Date: 2026-08-05

## Why

Two gaps, both about the app being visible outside its own window.

Tranlix has no icon at all: no asset catalog, no `.icns`. In the Dock and in
Cmd-Tab it shows the blank placeholder, which is what an unfinished app looks
like.

And a recording lives entirely inside the app window. Once that window is behind
a Zoom call there is nothing on screen saying a session is open, and no way back
to it other than hunting through the Dock. That is a bad property for an app
whose whole design principle is that no recording is ever lost.

## Part 1 — App icon

### The mark

A waveform on the left turning into lines of text on the right, on a deep indigo
field. It says what the app does — audio becomes transcript — and it survives
being shrunk to 16 px, because at that size it reads as two blocks of texture
rather than as a detailed drawing.

Colors: indigo `#26246B` background, waveform bars in the indigo-300/400 range,
text lines in near-white at descending opacity.

### Format

macOS 26 renders app icons through Liquid Glass. An icon supplied as a flat PNG
in a classic asset catalog still works, but it stays flat next to every other
icon on the system. The modern container is the Icon Composer `.icon` bundle,
which the build system recognises as file type `folder.iconcomposer.icon` and
compiles with `actool`.

`AppIcon.icon` is authored by hand rather than through the Icon Composer GUI, so
the icon is diffable text plus SVG and can be regenerated from source. The
schema comes from `IconComposerFoundation`: a top-level `fill`, a `groups` array
of at most four groups, each group holding `layers` that reference an
`image-name` in the bundle's `Assets/` directory, with per-group `specular`,
`translucency`, `blur-material` and `shadow`.

```
App/AppIcon.icon/
  icon.json          background fill, two groups
  Assets/
    waveform.svg     the four bars
    lines.svg        the three text lines
```

Two groups rather than one flattened image: the system applies depth and
specular highlights per group, so splitting the waveform from the text is what
makes the icon read as layered glass instead of a sticker.

SVG assets must contain no `<text>` elements — Icon Composer rejects them. All
shapes are rectangles.

### Wiring

`project.yml` gains a source entry for `App/AppIcon.icon` with `type: file` and
the build setting `ASSETCATALOG_COMPILER_APPICON_NAME: AppIcon`.

`type: file` is not optional. XcodeGen 2.46 has no entry for the `.icon`
extension in its file-type table, so left to itself it treats the bundle as a
directory and recurses into it, adding `icon.json` and the SVGs as individual
files. `type: file` forces a single file reference.

### Verification and fallback

The hand-written `icon.json` and the XcodeGen wiring are both unverified
assumptions. Both are checked the same way: run `xcodegen generate`, inspect the
generated `.pbxproj` for a single file reference, build, and confirm the icon
renders in the Dock.

If either fights back, the fallback is a classic asset catalog:
`App/Assets.xcassets/AppIcon.appiconset`, generated by `scripts/icon.sh` from a
composed SVG with `rsvg-convert`, with the PNGs committed so a plain checkout
builds without extra tools. The mark is identical either way; only the container
changes.

## Part 2 — Menu bar indicator

### What it shows

A status item appears in the system menu bar for exactly as long as a session is
open, and disappears when the session is finished. Open includes paused: a
paused session is still a session that has not been closed, and that is the
state most in need of a reminder.

- Capturing: a red dot followed by elapsed time as `HH:MM:SS`.
- Paused: an orange pause glyph, time frozen.

Clicking opens a short menu:

```
Sesión sin título — Grabando
01:12:34
---
Ir a la grabación
Pausar
Marcador
---
Finalizar            (only when paused)
```

`Finalizar` appears only while paused, mirroring `RecordView`: stopping is two
deliberate actions, so a stray click in the menu bar costs a pause and never a
class. The menu bar must not become a shortcut around the one rule the rest of
the app is built on.

`Ir a la grabación` activates the app, brings the main window to the front, and
selects the record screen in the sidebar.

### State ownership

`RecorderViewModel` currently comes to life as `@State` inside `RootView`, which
puts it out of reach of the `App` scene where a `MenuBarExtra` has to be
declared. It moves up to `TranlixApp` and is passed down into `RootView`.

One owner, two readers. The alternative — a second observable mirroring
`isRecording` / `isPaused` / `elapsed` for the menu bar — would mean two copies
of the same truth that can disagree, and menu actions that bypass the view model
would leave its state stale.

Sidebar selection has the same problem in miniature: `Ir a la grabación` needs to
set it, and it is `@State` local to `RootView`. A small `AppNavigation`
observable holding `selection` moves into `AppEnvironment`; `RootView` binds to
it instead of owning it.

### Implementation

`MenuBarController`, an AppKit object over `NSStatusItem`, created by the app and
following the recorder through `withObservationTracking`.

The first plan was SwiftUI's `MenuBarExtra`, with `NSStatusItem` as a fallback if
the label came out wrong. Two things could come out wrong: SwiftUI renders a menu
bar label into a template image, which is monochrome by definition and would cost
the red dot — the one thing that makes the indicator legible at a glance — and
proportional digits would resize the item every second.

The fallback was taken before writing the `MenuBarExtra` version, because the
plan for choosing between them was to look at the menu bar, and screen access was
not available. `NSStatusItem` makes both properties true by construction rather
than by inspection: a non-template `NSImage` keeps its color, and an attributed
title with `monospacedDigitSystemFont` cannot jitter. Measured on the real code:
the dot's centre pixel is `1.00, 0.32, 0.30` and the item is 76 pt wide at
`00:00:59`, `01:12:34` and `09:59:59` alike.

The cost is that the menu is built in AppKit — `NSMenuDelegate.menuNeedsUpdate`,
rebuilding on open rather than on every tick, so a menu that is on screen never
flickers and a menu that is closed costs nothing.

### Closing the window

`applicationShouldTerminateAfterLastWindowClosed` returns `true` today, so
closing the window quits the app. A menu bar indicator invites exactly that —
close the window, keep recording, come back later — and today that would end the
session instead.

It changes to return `false` while a session is open. Closing the window then
leaves the recording running with the status item as the way back. With no
session open the old behavior stands, so the app does not silently turn into a
background agent.

The app stays a regular app: no `LSUIElement`, the Dock icon remains.

## Part 3 — Cleanups this pulls in

**Elapsed time granularity.** `startPolling` writes `elapsed` every 80 ms, but
every reader formats it to whole seconds. With the menu bar added that is twelve
redundant re-renders a second in two places. `elapsed` is written only when the
whole second changes; levels keep polling at 80 ms because the meters need them.

**One formatter.** `HH:MM:SS` formatting is inline in `RecordView` and the menu
bar needs the same string. It moves to `TranlixModel` as a pure function, which
also puts it under test — the App target has no test target, `TranlixKit` does.

## Not doing

- No `.icns` for anything outside the app bundle; the DMG background and
  installer art are a packaging concern, not this one.
- No global hotkey and no menu bar popover with meters. The menu is a menu.
- No configurable "dot only" mode. If the width turns out to bother in practice
  that is a one-line change later, and guessing at it now adds a setting nobody
  asked to tune.
